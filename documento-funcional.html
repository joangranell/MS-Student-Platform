Documento Funcional y Técnico: MS Student Platform

Especificación de arquitectura, experiencia de usuario (UX/UI), motor de evaluación y modelo de datos para el simulador de certificaciones oficiales de Microsoft Data & Fabric.

1. Visión General y Propósito

MS Student Platform es una Single Page Application (SPA) estática, sin dependencias pesadas de servidor, diseñada para replicar con precisión tanto el entorno psicológico y visual de los exámenes oficiales de Microsoft (Pearson VUE) como el entorno de aprendizaje guiado de Microsoft Learn.

DP-900 Fundamentals

Conceptos de datos relacionales, no relacionales, cargas transaccionales vs analíticas en Azure.

DP-600 Associate

Microsoft Fabric Analytics: Lakehouses, Warehouses, modelos semánticos, DAX, Direct Lake y gobernanza.

DP-700 Associate

Microsoft Fabric Data Engineering: Ingesta en tiempo real (Eventstreams, KQL/Eventhouse), PySpark, orquestación y seguridad.

2. Sistema de Perfiles de Usuario (Sin Contraseña)

La plataforma permite que varios estudiantes (o una misma persona con distintos perfiles de prueba) utilicen la aplicación en el mismo navegador manteniendo su progreso aislado en localStorage.

Funcionalidades del Perfil

  • Selector rápido en el Header y Pantalla de Bienvenida: Cambio de perfil en 1 clic ("¿Quién estudia hoy?").
  • Creación/Edición sin fricción: Nombre, Avatar/Iniciales, Color de acento y Certificación Objetivo principal.
  • Estadísticas aisladas por perfil: Historial de exámenes, nota media (escala 100–1000), racha de estudio y porcentaje de dominio por cada bloque oficial.
  • Bolsa personal de "Preguntas Falladas" y "Favoritas": Cada perfil acumula sus propios fallos para el modo de repaso selectivo.
  • Exportar / Importar JSON de Perfil: Permite llevar el progreso a otro ordenador fácilmente.

3. Modos de Ejecución: Modo Examen vs. Modo Estudio

El usuario configura su sesión desde el Dashboard eligiendo Certificación (o mezcla), Cantidad de preguntas (10, 25, 45, Todas) y el Modo operativo.

3.1. Modo Examen Oficial (Simulación Pearson VUE)

  • Sin ayudas ni feedback durante el test: No se muestra si la respuesta es correcta hasta entregar el examen completo.
  • Temporizador real: Calculado proporcionalmente al número de preguntas (ej. ~1.8 min por pregunta, configurable).
  • Marcado de preguntas: Casilla "Marcar para revisión" (Mark for Review) y opción de tachar respuestas descartadas (Strikethrough con clic derecho o icono, igual que en Pearson VUE).
  • Pantalla intermedia de Revisión (Review Screen): Antes de finalizar, muestra la cuadrícula de preguntas (Contestadas, Sin contestar, Marcadas para revisión) permitiendo saltar a cualquiera.
  • Puntuación Oficial Microsoft: Escala de 100 a 1000 puntos (corte de aprobado en 700 puntos / 70%) con gráfico de barras por cada área de habilidad oficial (Skills Measured).

3.2. Clasificaciones Propuestas para el "Modo Estudio"

Para maximizar la retención técnica, proponemos 5 sub-modos de estudio especializados:

Sub-Modo de Estudio Filtro / Lógica del Motor Comportamiento Pedagógico
1. Lo Básico (Fundamentos y Conceptos) Filtra preguntas con difficulty: "basic" Ideal para empezar una certificación. Valida definiciones clave, arquitectura base y elección del servicio correcto sin trampas complejas.
2. Lo Más Difícil (Arquitectura, Código y Casos) Filtra difficulty: "hardcore" + preguntas con código (DAX, SQL, KQL, PySpark) y escenarios largos Entrenamiento de alto rendimiento: preguntas con distractores muy sutiles, optimización de rendimiento, permisos RLS/OLS/CLS y casos de estudio.
3. Por Dominio Oficial (Skills Measured) Selector de bloque temático oficial de la guía de Microsoft Permite atacar únicamente el bloque flojo (ej. solo practicar "Real-Time Intelligence / KQL" en DP-700 o "Semantic Models & DAX" en DP-600).
4. Clínica de Fallos ("Redención") Extrae de failedQuestionIds del perfil activo Genera un test exclusivo con las preguntas que el estudiante ha fallado anteriormente. Al acertar una pregunta en este modo, el usuario decide si retirarla de su lista de fallos.
5. Laboratorio de Código (SQL / DAX / KQL / PySpark) Filtra preguntas con hasCodeSnippet: true Enfocado 100% en completar fragmentos de código, funciones ventana, medidas DAX (`CALCULATE`, `USERELATIONSHIP`) y consultas Kusto.
Feedback Instantáneo en Modo Estudio

En cualquiera de los sub-modos de estudio, al pulsar "Comprobar respuesta" se revela al instante la opción correcta en verde, por qué las demás opciones son incorrectas, el bloque teórico completo y los enlaces directos a la documentación oficial de Microsoft Learn.

7. Estrategia para un Repositorio de Preguntas Muy Fuerte (+ Skills de Microsoft)

Como bien indicas, el simulador vive o muere por la calidad técnica y el realismo de sus preguntas. Las preguntas superficiales no preparan para el examen real de Microsoft (especialmente en DP-600 y DP-700, donde abundan escenarios con código DAX, KQL, PySpark, T-SQL, XMLA, Deployment Pipelines y Direct Lake).

¿Qué Skills o MCPs de Microsoft podemos usar?

  • MCP Oficial de Microsoft Learn (microsoft-learn MCP Server): Permite consultar en vivo la documentación oficial de Microsoft Learn para extraer límites exactos, tablas comparativas y URLs reales verificadas.
  • Skill de Antigravity para Generación de Exámenes Microsoft: Podemos crear una Skill dedicada en tu workspace (.agent/skills/ms-exam-generator/SKILL.md) con la rúbrica oficial de redacción de exámenes de Microsoft (estilo Pearson VUE: Contexto técnico + Problema/Restricción + Pregunta directa + 1 Respuesta Correcta + 3 Distractores plausibles basados en errores comunes).
  • Guías de Estudio Oficiales (Study Guides): Alinear el 100% de las preguntas con los pesos porcentuales actualizados de Microsoft para DP-900, DP-600 y DP-700.

Arquitectura Escalable del Banco de Preguntas

  • Carga Modular o Unificada: El motor cargará data/questions.json, pero también permitirá fusionar bancos modulares (dp900.json, dp600.json, dp700.json) o importar paquetes nuevos desde la propia interfaz.
  • Cobertura de Código Real: Incluiremos bloques formateados de T-SQL (`COPY INTO`, `OPENROWSET`), DAX (`CALCULATE`, `TREATAS`, Time Intelligence), KQL (`summarize`, `arg_max`, `mv-expand`, Eventstreams) y PySpark (`mssparkutils`/`notebookutils`, `MERGE INTO` Delta).
  • Explicación por Opción (Rationale): No solo explicamos por qué la correcta es válida, sino por qué las otras 3 opciones son falsas (clave para aprobar en Microsoft).
